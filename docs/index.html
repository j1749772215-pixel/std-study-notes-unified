一、我们是怎么做出这套效果的（核心做法实录）

供 Mac 端与听力线程直接对照复用，避免重复踩坑。

第 1 步 · 可读性排绝对第一 先用“零基础第一次看”的视角重写正文：先讲「为什么这么做 / 老师怎么一步步想出来的」，再给结论和口诀；绝不为了刷 div 数量或脚本指标做“换皮不换骨”。
第 2 步 · 删凑数图 + 完成态裁切 + 看图拆板书 只保留“光靠字说不清”的完成态截图（裁掉黑边、WPS/菜单栏、Dock、字幕、人像），并且每张图下必配「🖍️ 看图拆板书」青蓝卡，把图里每一笔红圈、蓝线、划掉线逐笔讲清。
第 3 步 · 清空橙色胶囊 + 绕开 Blue Topaz 透明白底 ① 正文彻底清空非代码反引号与 <code>（消灭刺眼橙色胶囊）；② 因为用户用的 Blue Topaz 主题会把原生 Callout 底色扒成纯白，所以一方面用内联柔和底色卡片让重点模块开箱即彩色，另一方面配了 cet4-rich-notes.css 补丁覆盖全库原生 Callout 与表格表头。

二、真实成品预览（节选自《四级写作 01 · 评分标准与根模板骨架》）

以下内容直接来自已验收通过的卷 1 真实代码，展示 6 种语义填充色块在实际笔记里的节奏与观感。

📌 卷 1 导读（靛蓝渐层底）
这一卷先把四级写作最基础的四件事讲明白：作文怎么算分、四级和六级套模板的界限、128 词三段式根模板怎么背怎么换，以及考场最易扣分的语法硬伤。
🖍️ 看图拆板书 · 老师蓝笔勾出的三段严丝合缝对应关系（青蓝底）
第一段蓝圈「综述」+ 双横线「学习、交流、社交」 先用一句话点明 translation app 使用普遍，紧接着把后文要讲的三个方向当目录一口气报出来。
第二段三条蓝线「学习」「日常交流」「社交或社会发展」 严格照着第一段报出的顺序逐层推进——先讲整体多重要，再落到个人交流好处，最后拔高到社会发展。
第三段蓝线「受益并推而广之」 不抛新观点，用一句话收尾并把全篇字数稳稳拉过 120 词。
第一段 · 1 句话（约 21 词）先用中心句直接点题，再接一个定语从句，把后文要谈的 3 个氛围词像目录一样摆出来。
第二段 · 3 句话（约 83 词）全文主体，严格照着第一段预告的顺序展开，用 Primarily（整体有多重要）、Moreover（落到个人层面怎么用）、At last（往社会层面拔高）三层往下推。
第三段 · 1 句话（约 24 词）不讲新观点，就是用一句「毫无疑问……」把中心词再提一遍、顺手收尾，开头短语 It admits of no doubt 也可以换成你自己最顺手的表达。
🔥 字数底线提醒：128 词已经够用，千万别在开头加空话「大帽子」（暖橙底）
四级题面硬性要求 30 分钟内写 120–180 词，而这套根模板原样套完就已经有 128 词，就算考场上发挥一般、一字不多加，也已经稳稳跨过 120 词底线。
⚠️ 避坑提示：bringing 千万不能删掉 -ing（珊瑚玫瑰红底）
第 3 句里的 bringing ... 是现在分词作结果状语，因为前面的主句已经有完整的主语和谓语动词了。背的时候千万不能把 -ing 删掉变成原形 bring，不然一句话里会出现两个谓语动词打架。
✅ 交卷前 2 分钟的三遍检查法（薄荷翡翠绿底）
第 1 遍 · 只查动词查双谓语（is ... be）、漏 be（will insufficient）或漏 -ed。
第 2 遍 · 只查介词和 its看到 to / of / despite 后绝不接完整句；区分 its 与 it's。
✍️ 手把手替换示范（暖杏琥珀底）
把中心词从 translation app 换成 online library，把三个氛围词换成 study / efficiency / remote book resources，整篇 80% 以上的英文骨架根本没动。
🧠 我理解：考场套用根模板的三步顺序（淡紫底）
Step 1先定第二段三层，再回头填第一段目录 → Step 2批量替换中心词 → Step 3固定词句一字不改。
老师原话　四级 P01　12:47（折叠在 <details> 内的深蓝原话卡）
「其实目的非常单纯，就是让阅卷子的老师，能够在他阅卷的几十秒钟之内快速的读出来，你整个文章的一个架构分布，以及它能够感受到一种很强的逻辑的一个推进性。」

三、Windows ↔ Mac Agent 双向交流协议

任何一端的 Agent（写作、听力、Mac 端）都可以直接通过 GitHub CLI 在 Issue #1 读对方最新进度、贴自己的成品预览页和改进提案：

# 1. 查看对方最新留言与规范更新 gh issue view 1 --repo j1749772215-pixel/std-study-notes-unified --comments # 2. 汇报自己的新成品 / 提议规范迭代 gh issue comment 1 --repo j1749772215-pixel/std-study-notes-unified -b "## [Mac/听力端] 同步汇报..." # 3. 拉取最新 SKILL.md 与成品样板 git pull origin main

如果另一端（如听力或 Mac）也做出了新的成品样板，只需往 docs/ 里新增一个页面（例如 docs/listening-sample.html）并推送，GitHub Pages 会自动发布，直接把链接贴到 Issue #1 就能互相验收成品。
